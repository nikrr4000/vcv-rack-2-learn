# 0.4 Подключаем агента

## Зачем

После урока ученик знает, как включается модуль MCP Server, на каком порту он слушает и что именно через него видит и делает агент. Агент читает патч из урока 0.3 и называет в нём модули, кабели и значения ручек. Это канал, по которому дальше идёт весь курс: агент смотрит, что ты собрал, и только в своей строке строит демо. Куска трека тут ещё нет: урок включает «глаза» агента.

## Пробник

1. **Что такое MCP Server в Rack?**
   - Верно: модуль, который открывает на твоём компьютере локальный сервер, и через него программа-помощник читает патч и вносит правки.
   - Неверно: «звуковой модуль, который играет сам». Заблуждение: у него нет звуковых выходов, только служебный выход Server heartbeat.
   - Неверно: «онлайн-сервис, куда уходит копия патча». Заблуждение: сервер слушает только локальный адрес 127.0.0.1 (твой компьютер).
2. **Агент видит у выхода напряжение. При каком условии?**
   - Верно: пока в этот выход воткнут кабель: Rack сообщает напряжение только для подключённого выхода.
   - Неверно: «всегда, у любого выхода». Заблуждение: у выхода без кабеля напряжения в ответе нет.
   - Неверно: «только если в патче есть Scope». Заблуждение: Scope — только окно для твоих глаз, агенту он не нужен.
3. **Что агент не может сделать?**
   - Верно: сохранить или загрузить патч и настроить модуль Audio (драйвер, устройство): этого в его инструментах нет.
   - Неверно: «добавить модуль». Заблуждение: это он как раз умеет, но по правилам курса только в своей строке.
   - Неверно: «повернуть ручку». Заблуждение: параметры он менять умеет, но по правилам курса только у собственных модулей.

## Понятие

Идея без модуля: программа-помощник и Rack — две разные программы, им нужен общий язык. Агент (Claude) говорит с Rack по протоколу MCP (Model Context Protocol): это набор именованных операций вроде «покажи модули» или «воткни кабель», которые одна программа предлагает другой. Модуль MCP Server — это сторона Rack: он поднимает на компьютере маленький HTTP-сервер, и в ответ на операции читает или меняет патч.

Факты (по README и исходному коду плагина, [nh-readme](https://github.com/Neural-Harmonics/vcv-rack-plugin)): плагин Neural Harmonics, модуль называется MCP Server и относится к утилитам; версия 2.1.1, лицензия MIT; слушает локальный адрес 127.0.0.1, порт по умолчанию 2600; в нём 17 инструментов (читать: статус, частота дискретизации, поиск в библиотеке, список модулей, параметры, кабели, раскладка; писать: добавить и удалить модуль, поставить параметры, добавить и удалить кабель, настройки раскладки).

Что агент не может: сохранять и загружать патчи (в README об этом упомянуто, но в коде такого инструмента нет), настраивать модуль Audio. Параметры он читает в сырых значениях, а ориентируется по отображаемому значению (`displayValue`), как оно показано на ручке. Все изменения Rack выполняет в своём потоке интерфейса: пока открыто меню или диалог, запрос агента может не пройти по времени.

Покажи схему: слева «Агент (Claude)», справа «Rack + MCP Server», между ними стрелка «127.0.0.1:2600» с подписями «читает / пишет». Подпиши: «только ваш компьютер».

Правила курса поверх возможностей: агент не трогает твои модули и кабели, а демо строит в своей строке снизу и потом убирает. Это защищено кодом (охранный хук), а не только инструкцией.

## Анатомия

Порядок: добавить модуль → порт → переключатель → выход → что видно из браузера Atlas. Не больше трёх новых терминов на шаг.

1. Добавление. Браузер модулей (Enter над пустым местом, урок 0.2): набери «MCP Server», плагин Neural Harmonics. Если в браузере его нет, вернись в урок 0.1: подписка и «Update all». У ученика курса модуль чаще всего уже стоит в патче: не добавляй второй. Два MCP Server на одном порту будут конфликтовать (проверить вручную).
2. Параметр `HTTP Port`. Целое число от 2000 до 9999, по умолчанию 2600. Курс ожидает 2600: на нём Atlas читает патч. Если порт занят другой программой, поменяй число и скажи об этом в Atlas (настройка порта Rack — в настройках, проверить вручную).
3. Параметр `Enable HTTP Server`. Переключатель вкл/выкл (значения 0 и 1). Пока он выключен, сервер не слушает порт и агент Rack не видит. Включи и подожди секунду.
4. Выход `Server heartbeat`. Служебный выход «пульс сервера»: по нему видно, что сервер работает. Это не аудио; к Audio его подключать не нужно (проверить вручную, что именно за сигнал). Подробности в карточке `VCVRackMcpServer.RackMcpServer.md`.
5. Что видит Atlas. На экране курса индикатор «Rack подключён / не отвечает» и список недостающих плагинов берётся из запроса к серверу. Если не отвечает: проверь переключатель и порт, закрой открытые меню в Rack.
6. Что агент делает в уроках. Читает патч всегда. Пишет только в «Демо» и «Слом» и только в своих модулях. Удаляет их после демо. Если охранный хук отказывает, это окончательный ответ: агент не обходит, а говорит тебе, что сделать руками.

Параллельно напомни по [vcv-manual-getting-started](https://vcvrack.com/manual/GettingStarted), как выглядит добавление модулей из библиотеки (урок 0.1) и что Audio настраивается руками (урок 0.3): агент в этом тебе не помогает.

## Демо

Агент пользуется инструментами vcvrack. Сначала читает, потом пишет в своей строке.

Чтение (ничего не меняет):

1. `vcvrack_get_status` — Rack отвечает, версия, число модулей.
2. `vcvrack_list_modules` — перечисли ученику его модули из патча 0.3: VCO, Audio 2 и сам MCP Server.
3. `vcvrack_list_cables` — два кабеля от `Sine` к входам Audio 2.
4. `vcvrack_get_params` для VCO ученика: назови `Frequency`, `Pulse width` и остальные, но не меняй. Значение `Frequency` читай по `displayValue`, не по сырому числу.
5. `vcvrack_get_module` для VCO ученика: у `Sine` есть `voltage`, оно меняется в пределах примерно ±5 В (синус), потому что кабель воткнут.

Запись, в своей строке (`vcvrack_get_rack_layout`, затем `new_row`):

Модули:

1. `Fundamental/VCO` (VCO A).
2. `Fundamental/VCO` (VCO B).

Кабель: выход `Sine` у VCO A → вход `Frequency modulation` у VCO B. На звук он не влияет (ручка FM у VCO B на 0), и в Audio ничего не идёт: громкость трогать не нужно.

Параметры VCO A: `Frequency` — целевое `displayValue` 110 Гц (сырое примерно -15; диапазон 11.562 Гц…5919.9 Гц, по умолчанию 261.63 Гц). Читай до и после, подбирай по цифре. Больше ничего не меняй.

Покажи ученику: `vcvrack_get_module` для VCO A: у `Sine` есть `voltage`, пять замеров с паузой около 100 мс — значения разные. Агент не слышит и не говорит «звучит»: ему доступны только цифры. В конце демо удали оба VCO.

## Покрути сам

Ученик делает руками, агент только читает.

1. Выключи `Enable HTTP Server` и попроси агента вызвать `vcvrack_get_status`. Что должно быть: Rack не отвечает. Включи обратно: ответ вернулся.
2. Правый щелчок по любому модулю (меню открыто) и попроси агента что-нибудь прочитать. Что должно быть: запрос может не пройти по времени; закрой меню, повтори — пройдёт. Это не поломка.
3. Сдвинь `Frequency` у своего VCO. Агент читает снова. Что должно быть: `displayValue` соответствует тому, что ты видишь на ручке.
4. Сними кабель от `Sine` к Audio 2 (один из двух). Агент читает кабели. Что должно быть: их стало на один меньше. Звук остаётся только в одном канале.

## Практикум

Задача ученика: чтобы в патче были VCO и Audio 2 из урока 0.3 с двумя кабелями от `Sine`, MCP Server включён на порту 2600, затем попросить агента пересказать патч своими словами: какие модули, какие кабели, на какой частоте VCO. Агент ничего не двигает: он называет модули и значения по данным Rack, не от себя.

## Проверка

Файл `checks/p0-04-agent.json`. Он проверяет патч из урока 0.3: VCO и Audio 2, два кабеля от `Sine` к входам Audio 2, `Frequency` VCO в пределах 80–1000 Гц, `Level` Audio 2 от -40 до 0 дБ, сигнал на `Sine` меняется. Сам MCP Server в проверку не вписан: если проверка вообще отвечает, значит сервер включён и Rack доступен по порту.

Комментируй результат с первого невыполненного пункта, по лесенке «вопрос, где смотреть, ответ»:

- Проверка не отвечает или «Rack не отвечает». Вопрос: включён ли `Enable HTTP Server`? Где смотреть: на модуле MCP Server и порт `HTTP Port` (2600). Ответ: включить переключатель, закрыть открытые меню, повторить.
- Нет VCO, Audio 2 или кабеля. Скажи, что патч из 0.3 пропал, и открой с учеником файл `vcv-0.3.vcv`.
- `Frequency` или `Level` не в диапазоне: как в уроке 0.3.
- Сигнал не меняется: проверь кабель от `Sine`.

## Слом

В демо-патче агента: удалить свой кабель между VCO A и VCO B (`vcvrack_delete_cable`, только свой). Попроси ученика найти, что изменилось, без подсказки: в `vcvrack_list_cables` исчез кабель, а `voltage` у `Sine` модуля VCO A пропало (у выхода без кабеля напряжения нет). Звук тут ни при чём. Вывод: агент читает данные Rack, а не угадывает, и по ним же видит, что цепь разорвана.
