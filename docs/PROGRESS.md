## Deviations

- The Rack app bundle lives in `~/Applications`, not `/Applications`; it is read (and run for the test instance) from there.
- Test Rack instance and `Rack -t` screenshots impossible in the sandbox (see open issues) → offscreen render harness with the real nanovg + fontstash; plugin smoke test loads `plugin.dylib` with the app's `libRack.dylib` (no window).
- Demo bus: the bus feeds the row-0 Audio module; every practice row gets its **own** Audio module before the bench (checks need a free «To "device output 1"», and the learner patches inside the row). Rack 2 lets several Audio modules share one device (`audio::Device::subscribe`); the host applies the carried-over device data to every Audio 2 in the lesson. Stereo bus (two VCA Mix) when a demo cable goes to output 2; more than 4 sounding blocks → a Mix sums several VCA Mix per side.
- Practice probes are sampled from the UI thread in the host's `step()` (like the REST checker), not in a module's `process()` — no engine-thread pointers to modules that a patch load can delete.
- Learner copies are saved by `APP->patch->save` (zstd .vcv). The layout hash of a saved copy is kept next to it (`Atlas/patches/<id>.hash`) instead of being read from the archive. The audio device is applied to the loaded patch's Audio modules after `load()` instead of being injected into the JSON before it.
- npm: the owner's npm config points at an internal registry; the compiler's deps are installed with `--registry https://registry.npmjs.org --cache $TMPDIR/npm-cache`.
- Tutor `claude` path: a separate setting `tutorClaudePath` (env `RACK_TUTOR_CLAUDE` wins, else the app's `claudePath`). The fixtures point only the Rack tutor at `vcv/tutor/stub-claude.mjs`, so the web runner's fixture runs keep their own stub.
- Tutor patch line: the plugin posts it with every question (bench + given modules, from the engine); without it the server summarises the whole patch from REST `:2600` (all modules except Atlas and MCP Server) — REST module positions do not map to pack rows cleanly.
- Model exchanges are logged by the server when a stream ends; FAQ answers («из урока») arrive as plugin `tutor` events and are logged the same way.
- `app/dist` was rebuilt (`vite build`, 2026-10-20 02:17) to check W8 in the browser. If the owner's Atlas service on 5175 serves this checkout, it already serves the new UI; with the old server process the Rack parts degrade (no tutor line, no Rack progress) until the service restarts.
- Long mono values (more than 12 characters, e.g. `To "device output 1"`) may break at spaces; short ones (`440 Гц`) never break. Same in C++ and Node.

- Fixes after W7 (main session): 0.4 anatomy of a second MCP Server → a story block (a second MCP Server in a lesson patch could fight for port 2600); three debug checks matched the wrong one of two identical modules and passed on the broken patch (4.5, 8.2, 9.3) → a pinning cable added to the check; Task width is now chosen by the compiler (14/16/18/20 HP) from a model of TaskView (title, steps, text, «Проверить» bar), 3 try blocks merged to 5 steps; validator compares whole tokens («8vert», «1V/octave», «Mid/Side») and knows Rack menu words; template checks: one module per ref, fine parameter search, snapshot points for non-linear params, display_in repair; resolver: a measured table wins over a guessed law.
- Clocked ratio table measured live (session row, module deleted): raw −34…34 → −96…−1.5, 1, 1.5…96 (35 values, sign = side). Stored in rack/course/calibration.json; 5.1 now uses display ±2. Which side divides is UNVERIFIED (the clock did not run when built over REST, see below).
